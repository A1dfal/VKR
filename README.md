# Выпускная квалификационная работа

Тема: **«Разработка системы анализа качества процессов разработки проектов с открытым исходным кодом»**.

> **Основной документ исследовательского этапа — [первая глава ВКР](artifacts/chapter1.docx).** Аналитический отчёт и таблица сравнения содержат данные и основания, использованные при анализе существующих средств и обосновании требований к системе.

В репозитории размещены результаты исследования проблемы выбора открытых проектов с учётом рисков информационной безопасности и внедрения бэкдоров. Рассмотрены существующие средства, выполнено сравнение их документированных возможностей и сформулированы требования к разрабатываемой системе.

Цель работы — разработать систему анализа процессов разработки проектов с открытым исходным кодом для формирования обоснованных рекомендаций об их использовании с учётом информационной безопасности и риска внедрения бэкдоров.

## I. Артефакты

### 1. Аналитический отчёт

Для чтения на GitHub: [analytical_report.md](artifacts/analytical_report.md).

Исходник Quarto с кодом R и данными исследования: [analytical_report.qmd](artifacts/analytical_report.qmd).

В сравнении рассмотрены **9 модулей и средств по 11 критериям — всего 99 оценок**. В выборку входят CodeScoring SCA с OSA, CodeScoring TQI, Snyk Open Source, Sonatype Lifecycle, Socket, GitHub Dependabot, GitHub CodeQL, OpenSSF Scorecard и OWASP Dependency-Track. Модули разного назначения оцениваются отдельно.

| Группа критериев | Что сравнивается | Критериев | Оценок |
| --- | --- | ---: | ---: |
| Технические сведения | Состав компонентов, известные уязвимости, вредоносные пакеты и статический анализ исходного кода | 4 | 36 |
| Процессы и участие | Защитные практики, вклад разработчиков, смена публикующих участников и участие организаций | 4 | 36 |
| Поддержка решения | Объект результата, проверяемое основание и действия по исправлению | 3 | 27 |
| **Всего** | | **11** | **99** |

Критерии связаны с вопросами потребителя компонента: какие проблемы известны, как принимаются изменения, кто участвует в разработке и на чём основан результат проверки.

В сравнении используются три значения:

- **«Да»** — возможность документирована для выбранного модуля и способа применения.
- **«Нет»** — источник прямо указывает соответствующее ограничение.
- **«Не установлено»** — сведений для подтверждения недостаточно.

Для каждой оценки сохранены основание, источник и раздел документа. При интерпретации учитываются границы модуля и способ получения результата. Например, определение зависимостей по проекту и импорт готового SBOM дают сведения о составе разными путями.

Отчёт также содержит обзор **четырёх научных исследований**, сопоставление возможностей аналогов с работой пользователя и обоснование **шести требований к системе**.

## II. Воспроизводимость и запуск

Отчёт и презентация подготовлены в **Quarto с выполнением кода на R**. Данные и функции включены в соответствующие файлы `.qmd`. Таблицы отчёта, сравнительные матрицы и числовые показатели презентации формируются из этих данных.

Для локальной сборки нужны:

- R версии 4.0 или новее;
- Quarto;
- пакеты R `knitr`, `rmarkdown` и `readxl`.

Для открытия и сборки файлов удобно использовать RStudio.

Если пакеты ещё не установлены, в консоли R выполните один раз:

```r
install.packages(c("knitr", "rmarkdown", "readxl"))
```

Откройте нужный файл `.qmd` из папки `artifacts` в RStudio и нажмите **Render**. После сборки рядом с исходником появится HTML-файл отчёта или презентации.

Из терминала в корне репозитория:

```bash
quarto render artifacts/analytical_report.qmd
quarto render artifacts/presentation.qmd
```

Команда `quarto render` выполняет код документа и собирает его HTML-версию. При сборке аналитического отчёта также обновляется версия `analytical_report.md` для чтения на GitHub.

Если рядом с отчётом находится `comparison.xlsx`, выполняется сверка с рабочей книгой. При сборке презентации проверяется согласованность её встроенных данных с `analytical_report.qmd`, если он находится в той же папке. Встроенные проверки останавливают сборку при расхождении данных.

В браузерной презентации стрелки переключают слайды, **S** открывает окно докладчика, **Esc** показывает обзор. Основной доклад заканчивается на слайде 12; слайды 13–15 используются при обсуждении результатов.
